## 架構整合（驗證過的做法）

2026-10～11 的架構整合把多步驟的機制整合成通用的元件。下表是那時驗證過的做法與它們現在在程式的哪裡，新寫的通用元件先沿用這些：

| 做法 | 現在在哪裡 |
|---|---|
| 事實由程式產生、模型只寫說明；句子的意思跟事實核對 | 數據分析（`analysis_job.py`、`claims.py`；在領域 session 裡執行的也照它核對）；有骨架的技能：每個節點的結果是腳本的輸出（數量由腳本算），回退的條件由程式照收據判斷（`composite.py`；中階照收據寫的彙整拿掉了，要不要加回見框架討論紀錄第 4 節）。句子的意思只有數據分析有 |
| 每條事實附出處（行號），程式核對名稱與數值，只把對不上的那幾條交回修一次 | 提煉（`extract.py` 的 `missing_tokens`、`_repair`）；依報告回答與領域 session 回報的 answers（`answers.py`，出處是 檔案:行號 或 #編號）；有骨架的技能的合約（抄的原文由程式核對，`composite.py`） |
| 「做完了沒」由程式判斷：每一步的檢查、最後的成功判準 | 低階照收據守門（`edg.py` 的 expect、complete）；回退的不收斂與熔斷（`composite.py`）；領域 session 的上限與擋重複（`domain_session.py`）；answers 的核對（`answers.py`） |
| 模型只填要填的欄位（schema 只有那幾個名稱），前面決定過的值沿用 | 領域 session 的回覆：state 三種之一、用不到的欄位寫空的；有骨架的技能的參數附原文由程式核對（`domain_session.py`、`composite.py`、`schemas.py`） |
| 中間產物與最終產物都存檔（`job.json`、`calls.jsonl`、`events.jsonl`） | `jobstore.py`：`logs/` 的 `extract_jobs`、`analysis_jobs`、`edg_jobs`、`domain_jobs` |
| 程式整理好的報告不再交給提煉 | `protocol.is_exempt_result`：數據分析的報告、交辦的結果（`DOMAIN_RESULT_HEAD`） |
