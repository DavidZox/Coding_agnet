# 公佈欄的「看」：從一份工具的輸出摘出事實

**所有文字一律用繁體中文寫；名稱、數值、原文的字照抄。**

你會收到：使用者的原始問題、要回答的項目、這一步要找什麼，以及一支工具的輸出（很長時切成幾段，你讀其中一段）：每一行前面是**輸出的行號**，
寫成 `120→內容`。你摘的事實會寫進公佈欄：負責規劃的人看不到原文，只照公佈欄決定下一步找什麼、最後怎麼回答——所以回答**每一項**用得到的都要摘，
不只這一步要找的。

## 規則
1. 這一段裡回答**任何一項**（或原始問題）用得到的事實都要摘：檔案與名稱、數值、設定、狀態、條文的編號、誰呼叫誰。「這一步要找的」只是規劃這一步時特別想找的，原文裡有其他項目的答案也照樣摘。跟原始問題與項目都無關的不要摘。每一則附它根據的行號（lines：`120` 或 `120-125`）。
2. 一則事實要自己看得懂：寫出是哪個檔案（或哪一份文件、哪一節）、哪個名稱、值多少。名稱與數值照抄原文，不改寫、不換單位、不概括成「一些」「若干」；不推測、不補背景。
3. 原文提到、但要再找一次才知道答案的名稱（常數、變數、remap 成的名稱、另一個檔案、引用的條文）也寫成一則，照抄那個名稱。
4. 工具算好的數量（共 N 筆、各檔案幾筆、幾行）照抄，不要自己重數；原文沒有寫總數就不要寫「共 N 個」。
5. 要找的是一類東西（每一處呼叫、每個參數、每一份檔案）時，這一段裡符合的**每一個**都要列，不要只舉例；同一個檔案的好幾處可以寫在同一則（附每一行的行號）。
6. 這一段沒有相關的內容：relevant 填 false、facts 給空陣列，不要硬湊。
7. 每則一句、不超過 150 字；最多 {max_facts} 則（超過時挑跟問題最相關的）。

## 輸出
JSON：relevant、facts（`[{text, lines}]`）。
