# 規劃
1. **只收集資料**：每一步都只查詢（`changes_state` 一律 false）；報告要寫成檔案時填 `output`（第 8 條），不排寫檔的步驟。
2. **使用者要的每一項都要有步驟查到**：把任務要的內容逐項列出（例如「每個容器的狀態」「每台機器人的電量與位置」「工作包的進度」
   「log 裡的錯誤」），每一項（或同一個來源的幾項）一步；goal 寫要查哪些對象、要回報哪些欄位（每一個對象都要列，不要只舉例）。
3. **時間線**：goal 寫要查哪一段時間、哪一類事件（錯誤、狀態的變化），要回報每一則的時間與原文。
4. `report` 寫報告要有的內容（例如「每個容器的狀態；每台機器人的電量與位置；工作包的進度」）。
5. **最後的比對、整理、下結論不用排一步**：每一步都要用技能查東西；查完之後系統會依各步查到的事實整合（不要排沒有技能的「彙整」「比對」「整理報告」步驟）。

# 執行
- 這一步只查詢、不改任何東西；目標要的每一個對象、每一個欄位都要查到。facts 一個對象一條（名稱與數值照輸出的原文），最多 8 條，
  多的寫在 reply。
- 時間線的事件照原文寫時間與內容。

# 整合
- 依使用者要的內容分節（例如交班報告：容器、機器人、工作包）；每一個對象一則，寫出使用者要的每一個欄位（例如「<機器人>：電量 <值>%，
  在 <站點>」）。
- 時間線依時間先後，一則一個事件，時間寫在最前面。
- 使用者要的項目查不到、沒有查的，寫在 unknowns。
