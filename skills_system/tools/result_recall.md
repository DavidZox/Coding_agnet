# 用途
每次工具回傳都存成完整原文（#編號）；大量的回傳另外在 system prompt 尾端的「工具使用檢索清單」留一句關聯描述。使用者的話在接續、追問或延伸某份存檔時——清單裡的舊紀錄
（「之前查的那個馬達後來怎樣」），或剛剛的提煉沒寫到的細節（「那預設用哪個模型」）——帶編號＋使用者的問題**原文**執行：系統讀那份存檔的**完整原文**（長的依結構切段、
幾個獨立 session 各讀一段再整合），以這個問題（連同前幾句對話）為錨點提煉，回給你重點（每條附原文的行號）與下一步建議。找特定字串在哪幾行才用 `result_grep`；
對話裡已經有使用者要的那個名稱或數值時直接回答，不用這個。

# 語法
`EXECUTE: scripts/result_recall_cmd.py <編號>[,<編號>…] "<使用者的問題原文>"`
* 編號：清單裡的 `#數字`（也接受 `latest`），跨 session 不重複，直接抄。要一起看好幾份才答得了（比較兩份清單）時用逗號隔開一次給（最多 3 份），會交給同一次提煉一起整合。
* 問題：使用者的話原封不動放進去，不要抄清單上的描述、不要改寫成關鍵字（系統會自動帶上使用者最新的一句話，這個參數是你想額外聚焦的點）。
* 語法已經寫在清單的規則裡，看到相關的一筆可以直接執行，不必先載入這份規格。

# 範例
`EXECUTE: scripts/result_recall_cmd.py 5 "隨便選一個腳本幫我做內容分析"`
`EXECUTE: scripts/result_recall_cmd.py 2,1 "tools 裡的每個技能在 scripts 裡都有對應的腳本嗎"`

# 回傳
`[tool result - 任務導向摘要]` 開頭，第二行註明「重新讀取存檔 #編號 的完整原文，針對「…」提煉」，其餘跟工具回傳的提煉相同：回答／相關事實（附行號，`result_view <編號> --from <行號>`
看原文）／錯誤／未涵蓋，結尾是下一步建議（例如「還需要之前的存檔 #N」→ 下一輪一起 recall）。有段落沒讀到時「未涵蓋」會寫行號：用更具體的問題再 recall（會重新挑段落）。
被壓縮的對話片段、附圖分析也存成存檔，一樣可以 recall（附圖的原圖沒有保存，只能根據當時的分析文字回答）。會記軌跡、產生新的存檔編號，但不另外記進檢索清單。

# 異常
* `#N 不存在`：編號抄錯，看檢索清單或 `result_list`。
* `#N 的原始檔已經超過保留上限被清掉`（工具回傳 200 檔／50 MB，對話片段另外保留 100 份）：告訴使用者這筆資料已經不在、需要的話重新執行當時的工具；不要換個編號亂試。
* 第一個參數不是編號、或沒有問題：`[ERROR]` 附用法，照用法重送。
* 提煉失敗（獨立 session 沒有回應）：訊息會寫原因；改用 `result_view`／`result_grep` 看原文，或稍後再 recall。
