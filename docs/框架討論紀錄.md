## 1. 方向（2026-11-23 使用者決定）

```
主 session ──任務（子目標、要回答的項目）──▶ 領域 session
     ① 選領域（可以多個）→ 程式載入這些領域的技能清單
     ② 從清單選「一個」技能＋參數
     ③ 程式執行（技能自己的骨架與回退）
     ④ 結果太長 → 分段 worker 提煉（太長再提煉）
     ⑤ 看提煉結果：回報／再選技能（回 ②）／再選領域（回 ①）
     每一步的狀態是固定格式，由程式管，全部存檔
主 session ◀──經過與結果──
     做完了回答使用者；還沒就帶著這次的經過再交一次
```

- 為什麼：三階層（高階分工、中階合約＋骨架＋判斷節點、低階執行器、沒有報告接子工作階段）每一層各有自己的協定與狀態，修一個地方要動
  好幾層；後面幾次改進（B、C、A′、A″）都沒有贏 A。使用者要先把基礎做好，再想怎麼往上加。
- 留下試出來有用的：程式組命令（技能＋參數表單，參數附原文、程式核對）、骨架把穩定的步驟寫死、收據讓檔案:行號由程式核對、提煉的事實
  附行號並核對、全部存檔。
- 補三階層試出來的弱點（設計筆記 2.55）：開放的 session 讀和答不穩 → 讀交給提煉；命令列參數寫錯 → 選技能用表單；花步數載入工具說明 →
  技能清單事先載入；沒有新資訊的重做沒用 → 領域 session 看完提煉的結果才決定下一步；第一步選錯最多 → 在迴圈裡改選。
- 風險：同一個 session 要選領域、選技能、決定做完，e4b 可能吃力；靠固定格式的狀態、上限、擋重複來管。分數用真實專案評測跟 A 比。

**第 2 步的做法**（照 F1～F6 實作時定的細節；設計筆記 2.56、架構說明第 15～17 節）：
- 程式：`agent_core/domain_session.py`（領域 session 的迴圈）、`composite.py`（有骨架的技能：從中階留下規格、合約的核對、骨架、回退）、
  `orchestrator.py`（主 session 這一側：交辦一節、擋工具、`run_task`、問使用者的接回、依報告回答的核對）、`edg.py`（只收工具節點）。
  拿掉：中階（`mid.py`、`judge.py`）、子工作階段（`sub.py`）、Web 的決策圖、它們的提示與測試。
- 上限：一次交辦最多用 10 個技能、選了領域之後最多再選 2 次、最多回 24 輪（含被擋下、交回改的）；資源的上限，不是調來讓某一題過的門檻。
- 參數：有骨架的技能用 params（每個附抄的原文，程式核對；原文是問題、子目標、項目與前面每一步交給它的結果）；單步的工具用 args
  （技能清單列每個工具〈語法〉的參數寫法）。args 開頭照抄了工具名稱或腳本路徑的由程式拿掉（冒煙測試：26b 照抄技能清單裡以工具名稱開頭的語法，
  一題浪費 7 步；之後技能清單只列參數的部分）。寫錯欄位的（有骨架的技能寫在 args、工具寫在 params）程式擋下、說明寫法、不執行（第 3 步之後改成參數表單，見下面〈建議 1 的做法〉）
  （第二次冒煙測試：26b 把有骨架的技能的參數寫成 JSON 放進 args，原本照空的參數執行、交回「必填還沒寫」，它照原樣再寫一次就被
  「一模一樣」擋下，一題 7 步、15 輪；擋下之後下一輪就改用 params，4 步、8 輪）。
- 有骨架的技能要使用者決定的事（必填的參數沒寫、路徑有好幾個或找不到、回退的 ask）不再問使用者，交回領域 session（附候選）：它照候選改參數、
  換技能或回報。0 筆照實交回（技能跑完、結果是 0 筆），由它換一條路——「0 筆算做完」的錯（設計筆記 2.54 的 4n ①）因此沒有了。
- 確認關卡照舊問使用者：會改狀態的工具停下來，主 session 轉問，回答之後接回同一步。
- 測試：`evals/domain/selftest.py` 15 項；完整的離線測試全過。

**建議 1 的做法**（第 3 步之後、第 3 輪定的；設計筆記 2.58）：
- 選技能的那一輪只寫名稱；程式接著把那個技能的參數表單接進對話，下一輪只填表單——有骨架的技能每個參數一欄（quote、value，參數名稱就是欄位），
  工具只有 args。一樣是領域 session 在同一段對話裡填（前面每一步的結果也是可以抄的原文），不另外開呼叫、不加層。
- 合約沒過的只把那幾個參數交回重填一次（其他照第一次填的），還是沒過就回到選技能，都不算一步；原文開頭抄了程式的標題（「【子目標】」）的拿掉再核對。
  沒抄原文、值就是預設值的當成沒提到（冒煙測試 e4b 照寫了「.」被退）；值是別的交回、寫明沒抄原文（不直接改用預設值，免得範圍變成整個專案）。
- 表單的那一輪不算在回的輪數裡（另外記 forms）：輪數上限的意思不變（領域 session 的決定最多 24 次）。
- 測試：`evals/domain/selftest.py` 15 項（「參數寫錯欄位」那一項換成「參數表單」）。
