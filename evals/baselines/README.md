> 寫給：每個階段結束時要確認「框架沒有變差」的人。`evals/phase_check.py` 跑完會拿這裡的數字逐項比；結果目錄（`evals/results/`）不進版控，
> 基準要跟著程式一起 commit，換了機器也比得了。

## 怎麼比

- 自我測試：有沒過的就是 ❌；通過數比基準少（測試被拿掉、或環境少了東西而略過）列成要注意。
- 維運：只跑一次時，基準裡大多會過（≥ 3/4）的情境這次沒過才列；跑好幾次時，通過率比基準低超過 1/3 才列（模型有隨機性，單次的差別多半是波動）。
  另外列：有禁止動作的、秒數中位數超過基準的 2 倍而且多 30 秒以上的（2026-10-23 的 `--watch 300` 就是這樣被看到的）、總分低於基準最低分的。
- 主對話：通過率比基準低超過 1/3 的情境。
- 工作流沙盒：同維運的規則（通過率、禁止動作、變慢）。
- 提煉：找到的比基準少、多列的比基準多、回答說的數量不對。
- 數據分析回歸：每份數據的每個評分項目，通過次數的比例比基準低就列。

## 什麼時候更新

階段 commit 之後、確認要注意的項目都看過（是波動或已經處理），用那一次（或那幾次）的結果更新：

```bash
python3 evals/phase_check.py --save-baseline evals/results/<時間>_phase_check [其他的結果目錄…] --label "第 3 階段（<commit>）"
```

維運最好用 3 次以上的結果一起更新（`--save-baseline` 給好幾個 `_ops_` 目錄會合成一份）；`reference_v5` 不會被覆蓋。

只更新其中幾項時加 `--only`（名稱同跑的時候；`workflow`、`extract`、`analysis`、`tools_live` 看冒號前面），其他的基準不動。第 3 階段只更新了自我測試與工作流沙盒：維運、主對話、提煉、數據分析這一階段只有一次完整的結果（都在第 2 階段基準的範圍內，維運主要 46/50、保留 18/20），不足以取代第 2 階段的多次基準。
