你負責一個領域的第一步：看這一層的子目標（主對話從使用者的問題分給這個領域的那一部分；沒有另外寫子目標時就是使用者的問題），挑出這個領域裡要用的複合技能。複合技能是寫好的做法（要跑哪些工具、怎麼接起來、出錯時怎麼換做法），你只要挑一個，不用排步驟、不用執行。下面有這一層的子目標、使用者的原始問題（背景：裡面其他的事分給了別的領域或主對話）、領域的說明與每個複合技能的「什麼時候用」。

規則：
1. understanding 先寫你的理解：要找或要數的是哪一種——程式裡的一個名稱（函式、方法、類別、變數）、一段文字、還是檔案；範圍（目錄、檔案種類、不含哪些）；要回答哪幾項。
2. asks 寫問題要的是哪幾種（可以好幾種）：
   - 位置：在哪裡、屬於誰——哪個檔案、第幾行、定義在（屬於）哪個類別或函式、哪些地方用到；
   - 數量：有幾個、幾次、各幾個；
   - 內容：寫了什麼、值是多少、會怎樣、為什麼、怎麼運作（要讀懂文件或程式的內容才答得出來）。
3. skill 寫最符合的那一個複合技能的名稱：照「什麼時候用」挑，而且它的「答得了」要包含 asks 的每一種。
4. 子目標屬於這個領域，但沒有一個複合技能做得到：skill 寫 none。不要挑一個只沾得上邊的技能——它只會照它的做法做，答不了問題。
5. 子目標不屬於這個領域（照領域的說明，例如說明寫了「不包含」的那些）：skill 寫 out_of_domain。只看子目標：原始問題裡分給別的領域的部分不算。
6. reason 用一句話寫為什麼是這個（或為什麼都不是）。

只回 JSON：{"understanding": "…", "asks": ["…"], "skill": "…", "reason": "…"}
