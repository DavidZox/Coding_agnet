# 技能撰寫規範（規格文件與腳本）

給寫技能、改技能的人看（主對話的模型看不到這份）。目標：**主對話的 AI 自己就能用每一個技能**——看規格就知道怎麼下參數，出錯時看
`[ERROR]` 的訊息與規格的「異常」就知道要換參數重試、改用別的技能，還是用一句話問使用者；之後常駐的工作（心跳）也照同一套用。

## 1. 規格文件（`skills_system/tools/<名稱>.md`，OKF 格式）

```markdown
---
type: Tool
title: 一句話的標題
description: 什麼時候用（主對話選技能時看這一句）
version: x.y.z
dependencies: ["docker", "ros2"]
---

# 用途      做什麼、跟相近的技能怎麼分（一兩段）
# 語法      `EXECUTE: scripts/<腳本>.py <參數>`，每個參數一行：意思、預設值、上限
# 範例      兩三個，涵蓋常見的用法
# 回傳      [PASS] 的第一行寫什麼、有哪幾節；[ERROR] 的寫法
# 異常      每一種會發生的錯誤 → 下一步（換什麼參數、先用哪個技能查、或問使用者什麼）
```

- 規格要精簡（800 字左右為原則）：每次載入都會進主對話的上下文。
- 參數的預設值、上限、逾時都要寫；腳本裡的數字改了，規格一起改。
- 會改變狀態的技能（建、刪、改、重啟、發布、送出）寫明「會先請使用者確認」，並加進 `agent_core/config.py` 的 `GUARDED_SKILLS`
  與 `NON_READONLY_SKILLS`；同一個技能有唯讀的用法（`docker_ctl status`、`ROS2_param get`）時，`agent_core/guard.py` 要放行那些用法。
- `SKILLS.md` 的一行描述是給主對話選技能用的：寫「什麼時候用」，不要寫實作。

## 2. 腳本的輸出（`skills_system/scripts/<名稱>_cmd.py`）

輸出是給模型看的文字，一行一行，長的輸出會由系統依結構切段、交給幾個獨立 session 提煉（`agent_core/extract.py`），所以要有固定的結構：

1. **第一行**：`[PASS]` 或 `[ERROR]` 開頭，一句話的結論與程式算好的數量（共 N 個、列出前 M 個、略過幾個、沒有權限的幾個）。
2. **分節**：長的輸出每一節一行 `## 標題（N 項）`，節裡一行一筆；表格的欄名接在節標題的下一行（切段時會把欄名帶到下一段）。
   多行的一筆（一則訊息、一段 traceback、一個區塊）以 `--- #序號` 開頭（`result_grep --block` 依它取整筆）。統計、結論在前，原始資料在後。
3. **有截掉就說**：只列前 N 個、只看最後 N 行、單行太長截斷時，寫在第一行或那一節，並寫怎麼看其他的（換參數、`--filter`、`--from`）。
   不要默默地截。
4. **數字由程式算**：數量、統計、比較、門檻判斷、排序都在腳本裡算好寫出來（「共 12 個」「第一則符合 #49」），模型照抄、不自己數。
5. **時間**：寫明時區或基準（`+秒`＝距離數據或觀察開頭）。
6. **狀態標記**（`[TARGET_CONTAINER]`、`[ANALYSIS_DATA]`、`[CWD_CHANGED]`…）只放在輸出的最後幾行：系統只認最後連續的標記行，
   原文（容器的 log、指令的輸出）裡剛好出現同樣的字不會被當成標記。

## 3. 錯誤

- 可預期的錯誤（參數錯、找不到、沒有權限、逾時、服務沒回應）：印 `[ERROR] 原因。下一步：…` 到 stdout，exit code 0。
  下一步要具體：「先用 docker_containers 確認名稱」「--duration 縮短到 10 秒」「請使用者確認要用哪一台車」。
- 參數錯時附上正確的用法（`USAGE`），USAGE 裡的腳本路徑要跟規格一致（大小寫一樣）。
- 不認得的參數、多出來的參數：回 `[ERROR]` 或在輸出最後一行明說略過了什麼（`CliParser.ignored_note`），不要默默忽略。
- 工具自己的錯誤訊息（stderr）原文附在後面（太長截尾），不要只寫「失敗」。
- 未預期的例外：`[ERROR] <技能> 未預期的例外：<型別>: <訊息>`，exit code 1。

## 4. 可以自己用（不需要人在旁邊）

- **不讀標準輸入**（`stdin=subprocess.DEVNULL`），不開互動式程式（編輯器、分頁器、`sudo` 問密碼）；`docker exec` 不用 `-t`。
- **每個外部指令都有逾時**，各技能的上限低於系統的 600 秒；逾時要結束整個程序群組（`start_new_session=True` ＋ `os.killpg`），
  不留背景程序；逾時時回傳已經拿到的部分並說明（「60 秒內只收到前 30 行」）。
- **不會自己結束的指令**（`tail -f`、`ros2 topic echo` 不加 `--once`、`ros2 topic hz`）：改用有時長的技能（`ROS2_topic_echo --duration`），
  或一定要帶 `timeout N`。
- 輸出用 `errors="replace"` 解碼（容器的 log、二進位檔不會讓腳本當掉）。
- 路徑：`~` 要展開；相對路徑相對於目前的工作目錄（harness 執行腳本時的 cwd）；容器內路徑與主機路徑分清楚（數據技能會依 bind mount 換算）。
- 寫檔只寫到參數指定的地方或 `logs/`，不要寫進使用者的工作目錄。

## 5. 測試

- 不用模型的測試在 `evals/skills/`（`python3 evals/skills/selftest.py`）：每個技能至少有一個 `[PASS]` 的情況與每一種 `[ERROR]` 的情況，
  檢查第一行的格式、下一步的提示、截斷的說明；需要容器的情況在沙盒（`evals/ops` 的 Docker-in-Docker）裡跑，沒有沙盒就略過並註明。
- 主對話真的用技能的評測：`evals/chat/`（假的外部世界）、`evals/ops/`（沙盒裡真的執行）。
