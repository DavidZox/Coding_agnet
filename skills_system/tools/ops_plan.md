# 用途
使用者想先看計畫（「先列出你打算怎麼做」「先不要動」）時用：把複雜的維運任務拆成 2～6 步，只規劃、不執行、不改變任何狀態；
計畫存成草稿，把計畫告訴使用者，同意後用 `ops_run`（不帶參數）執行。計畫的步驟都只查詢（不會改變任何狀態）時不用等使用者，系統直接執行、回傳每一步的結果。要直接做的任務用 `ops_run "<任務>"`（它自己會先規劃、給使用者確認）。

# 語法
`EXECUTE: scripts/ops_plan_cmd.py "<任務描述>"`
* 任務描述：照使用者的原話寫完整（名稱、路徑、數值、條件，例如「先備份」「不要動 tb2」都要帶到）。

# 範例
`EXECUTE: scripts/ops_plan_cmd.py "把 nav 參數檔的 max_vel_x 改成 0.5，改之前先備份，然後重啟 nav2_test 容器並確認它有起來"`

# 回傳
`[PASS] 計畫（N 步）：…` 每一步的標題、會不會改變狀態、技能、做完的檢查。把計畫告訴使用者；同意後 `scripts/ops_run_cmd.py`（不帶參數）執行。
要改計畫：用 ops_plan 帶著修改後的要求重新規劃（新的計畫取代舊的）。

# 異常
規劃不出可以執行的步驟：`[ERROR]`，改成自己用技能一步一步做。
